Handling Adversarial Chaos

The pipeline is designed to conquer the reality of informal trading chats: typos, slang, spam, and fragmented thoughts.

1: Self-Correction

Users often correct typos in follow-ups. Context assembly merges them so the LLM extracts only the final value.

alice: Selling Claude API, 4.0/unit.
alice: Typo sorry, meant 3.8.
Result: Extracts sell for Claude_API at 3.8.

2: Missing Units & Slang

Informal markets use slang (e.g., "8-card", "below 4"). Raw strings are preserved when precise parsing fails.

carol: Got 8-card A100s, spot.
bob: Looking for 500k OpenAI, below 4.
Result: Maps "A100s" to A100_GPU. "below 4" is stored in raw_price_str.

3: Broker Spam Deduplication

Brokers spam identical messages. A content hash suppresses duplicates across groups.

broker_x: Discounted MJ subs... (grp_A)
broker_y: Discounted MJ subs... (grp_B)
Result: Only the first message generates a signal. Hash match drops the rest.

4: Historical & Chatter

Complaints or reminiscing about past prices should not affect the current market depth median.

dave: Remember when OpenAI was 2.0? Crazy.
frank: AWS quotas are so annoying lately.
Result: Intent marked historical and irrelevant. Excluded from aggregation.

5: Bundled Offers

A single message contains multiple resources, distinct quantities, and different discount semantics.

grace: Got AWS $100k accounts at 30% off, and throwing in a GCP $50k account for 25% off.
Result: Generates two distinct signals (AWS_Compute and GCP_Compute).

6: Multi-party Threads

Replies form a thread where the final commitment relies on the root resource message.

henry: Need $120 OpenAI stock.
ivan: I have 5. Standard rate?
henry: Deal, PM me.
Result: Extracts transaction_completed at price 120.

7: Contradictory Quotes

Users disagreeing on current rates. Both are extracted; median aggregation naturally handles the spread.

user_j: Claude API is 3.8 today.
user_k: No, I can get it at 4.2.
Result: Retains both prices. Dispersion and range (3.8 - 4.2) are shown in UI.

8: Alias vs Unknown

Known slang is mapped to a canonical ontology. Totally new resources are flagged as unknown but tracked.

user_l: Sonnet quota available.
user_n: New model X access, 20 slots.
Result: Maps "Sonnet" to canonical. Stores "model X" as unknown:model_x.

9: Irrelevant Numbers

Not every number is a price or volume. The LLM must discern intent to avoid hallucinating false offers.

user_o: The model had 2 million downloads last month.
Result: Ignored. no_actionable_signal returned.

10: Incomplete Reply Chain

When the parent message is missing from the stream, the AI extracts what it can but lowers confidence.

user_q: Yes, I can take 200 at 3.8. (reply to unknown)
Result: Extracts price and volume but leaves resource as unknown.

Golden Dataset & LLM Calibration

Because LLMs are non-deterministic, modifying prompts or switching models (e.g., from Gemini Flash to Pro) can cause silent regressions. We prevent this by enforcing a Golden Regression Suite.

  • Hand-labeled Golden Cases: Contains highly adversarial chats (slang, corrections, bundles) mapped to exact expected JSON outputs.
  • Calibration Pre-flight: The Streamlit UI forces a Run Golden Tests check before starting the live stream. If the LLM extraction accuracy falls below 75%, the pipeline refuses to run.
  • Cost-Aware Routing: During live runs, if the primary model's confidence drops below threshold on complex chats, the pipeline automatically routes the context to a heavier fallback model (Pro).
