Handling Adversarial Chaos

The pipeline is designed to conquer the reality of informal trading chats: typos, slang, spam, and fragmented thoughts.

Scenario A: Self-Correction

Users often make typos and correct themselves. Time-window context assembly groups these together so the LLM extracts only the final corrected value.

alice: Selling Claude API credits, 4.0 per unit, have about 500k.
alice: Typo sorry, meant 3.8 per unit not 4.0
Result: Extracts single sell signal for Claude_API at price 3.8.

Scenario B: Slang & Missing Units

Informal markets use slang (e.g., "8-card", "below 4"). Normalization maps aliases, while the schema retains raw strings when precise parsing fails.

carol: Got 8-card A100s, spot, anyone interested?
bob: Still looking for 500k OpenAI credits, below 4 if possible.
Result: Maps "A100s" to A100_GPU. "below 4" is stored in raw_price_str.

Scenario C: Broker Spam

Brokers spam identical messages across groups. The normalization layer calculates a content hash and suppresses duplicates within a 2-hour window.

broker_x: Discounted Midjourney... (grp_ai_trading)
broker_x: Discounted Midjourney... (grp_secondary)
broker_y: Discounted Midjourney... (grp_resellers)
Result: Only the first message generates a market signal. Subsequent identical hashes are dropped.

Scenario D: Multi-party Threads

Replies form a thread where the final commitment relies on the root resource. Reply-chain assembly handles this seamlessly in one LLM call.

henry: Need $120 OpenAI accounts, anyone have stock?
ivan: I have 5. Standard rate?
henry: Deal, PM me.
Result: Extracts a transaction_completed signal for OpenAI_Credits at 120.
